# 数位化封包供应器：阶段交付记录

本分支记录封包供应器的实现范围、边界和验证结果。未列入“已接入”的行为仍不会被封包路径调用。

## 已接入的公共路径

- 通过项目插件生命周期注册适配器，按已安装 Mod 隔离可选 API。
- 复用加工样板的配方类型和配方 ID；兼容配方不受普通类型记录开关关闭的影响。
- 独立供应器有 36 个样板槽和两行共 18 个回收槽。回收槽容量、NBT 和菜单资源数量均使用 `long`。
- 独立供应器只发现相邻机器；自适应供应器可识别同维度连接器目标，没有扩展 ConnectorLink 的存档格式。
- 自适应封包分派先尝试远程目标，再尝试相邻兼容机器，不进入普通库存投料路径。
- 每个机器类别拥有独立轮询游标和顺序优先策略状态；只有成功接受完整输入后推进游标。
- 接单时固定机器和已选部件；原子预留共享基座、注入器等物理位置，阻止重叠机器竞争。
- 任务保存配方引用、已投料进度、尚持有的输入和已回收输出；拥有数量按 `BigInteger` 记账，物理机器操作使用有界数量。
- 掉落物通过真实机器调用范围和任务 UUID 追踪；不同任务的掉落物禁止合并。
- 可重复诊断由独立配置 `developer.packagedCraftingLogging` 控制。
- 拆除时将封包任务、回收库存和完整 `BigInteger` 数量写入维度存档恢复凭证；凭证绑定原维度、位置和供应器类型，只能成功兑换一次。
- 恢复凭证不会复制正在执行的任务资产；机器结构仍在时，恢复前保留占用，恢复后继续沿用原任务 UUID 和物料账本。
- 所有封包路线共用机器拆除清理：已占用的主机或基座被替换时释放整组占用，并记录原任务的结构已拆除，防止其再次占用同坐标新放的机器。区块卸载、同方块属性变化不触发清理；旧存档中已加载且变成空气的占用位置每秒检查一次。
- 结构拆除后，原任务退回供应器仍持有的未投料和已回收产物，然后结束封包操作；不会补发已投进世界的材料，也不把 CPU 的合成目标伪造为完成。回收库存满时保留待返还资产；供应器恢复凭证中的任务恢复后同样执行该清理。
- 龙研发现阶段不修改原生绑定，投料时由原生 `updateInjectors()` 替换失效或闲置旧绑定；旧核心未加载或仍在合成时等待。Mekmm 旋转机在原封包占用消失后清除旧模式锁标记。

## 后续待完成的工作

1. 继续验证第三方配方和宿主生命周期；本分支仅保留封包派发、机器占用、物品追踪、回收和恢复等核心流程的新增测试，不再保留第三方机器专项测试及专用测试配方。
2. 扩展拆除恢复到所有供应器类型、失败任务和跨重启占用释放；当前普通 AE2 大数量掉落路径仍存在数量截断风险，不能作为完整恢复实现。
3. 验证网络满、卸载、重启、删除链接和更换内装供应器；尤其检查持久化任务与维度占用记录的一致性。
4. 完成三位一体超大订单、绑定输入、不可合批机器持续执行的端到端验证。存在 BigInteger 记账并不代表全部大数量入口已验证。
5. 补齐实际 JEI/EMI 分类与服务端配方 ID 映射、辅助耗材和返还物编码验证。
6. 完成配方重载缓存失效、目标索引及结构变化的性能与正确性验证。

## 依赖约定

新增依赖采用远程坐标，官方 Maven 优先，未找到可用官方发布时使用 CurseForge，Modrinth 最后考虑；不使用本地 jar。测试编译依赖集中声明，别名不带 `-packaged` 后缀。Gradle 缓存由环境变量 `GRADLE_USER_HOME` 提供。
