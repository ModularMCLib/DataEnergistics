# Digital Packaged Pattern Provider

The Digital Packaged Pattern Provider sends AE2 pattern orders to real third-party machines. It checks recipes, structures, machine claims, inventories, and energy conditions, accepts the complete task, inserts the inputs into the target machine, and returns real outputs and reusable contents.

## Dispatch flow

1. The CPU prepares the inputs.
2. The provider checks the pattern, machine, links, structure, inventory, and conditions.
3. After the checks pass, the provider accepts the full task and claims the machine.
4. The adapter inserts the inputs into the real machine.
5. The native machine performs the recipe.
6. The adapter collects outputs, containers, and declared returns.
7. The provider stores the returns in its return inventory.
8. Outputs return to the ME network or to the waiting CPU.

If a preflight check fails, the provider rejects the order and the inputs remain in the CPU. A CPU holding materials while the provider stays empty usually means that the machine, link, recipe, or inventory check failed.

## Placement and connections

An independent packaged provider discovers only adjacent machines. Enable the side facing the target machine; the provider and target must be directly adjacent with no cable, chest, or air between them. Build the target's native multiblock structure, bases, injectors, light path, and energy supply separately.

An Adaptive Pattern Provider can contain a packaged provider and use a [Distribution Connector](6.19_data_distribution_connector.md) to bind its full block form to a target machine. A remote link replaces only physical adjacency. It does not replace the target's native multiblock structure, power, or other requirements. The provider and target must share a dimension and their chunks must remain loaded.

## Pattern encoding requirements

1. The pattern must contain the correct recipe category and exact recipe ID. Transfer the recipe from JEI or EMI when possible.
2. A processing pattern that only hand-fills inputs and outputs without recipe identity cannot enter the packaged route.
3. Editing inputs or outputs does not automatically change the stored recipe ID.
4. Re-encode patterns written with an old matching format.
5. Encode the normal one-round amount; batching is decided by the target machine's declared capacity.
6. Declare buckets, containers, catalysts, tools, and retained inputs according to the machine section below.
7. After acceptance, do not move task inputs, returns, or outputs through another pipe, machine, or player inventory.

Output slots can use exact, ID, or Tag matching, but amounts must still be correct. ID matching ignores component differences only; Tag matching must be declared by the recipe. Neither mode bypasses native input or structure checks.

## General admission conditions

- The provider is online and not blocked by a crafting lock.
- The target machine and every inspected chunk are loaded.
- No other packaged task owns the machine or shared bases, injectors, or pedestals.
- Input and output inventories are normally empty.
- The target machine can select the recipe recorded by the pattern.
- Energy, mana, source, aura, light, souls, experience, and structural bonuses are supplied by the native machine or its surrounding setup.
- Shared machine components participate in the ownership check.

After acceptance, task inputs belong to the current packaged operation. Do not take inputs from the machine or pull outputs through another route.

## Dynamic batching and capacity

Capacity changes with energy, input slots, output slots, stack limits, structure state, and native progress. It is not a fixed 64. One machine is still owned by one packaged operation at a time, but one operation may contain several logical rounds.

The main routes that currently declare batching include:

- six Mekanism More Machines Large machines, which refill input ports and drain outputs according to native parallelism;
- Ars Nouveau Elven Gateway, limited by material, output stack, and available mana;
- Botania Mana Pool, which invokes native conversion item by item;
- Occultism Spirit Fire, which processes a stack within input and output limits;
- Actually Additions Atomic Reconstructor, which computes a stack from energy, stack limits, and lens cost;
- other adapters when their native route can prove a safe capacity.

Petal Apothecary, Runic Altar, Terrestrial Agglomeration Plate, and routes without a safe batch entry remain single-round operations. Avaritia and Extended Crafting do not loop output extraction to imitate batching; complex return recipes are also kept single-round.

Compressor tiers cannot substitute for each other. Treat complex returns as actual native results and declare every required primary output accurately.

### Mekanism More Machines

Large machines require a complete casing, input/output ports, and power. The adapter refills ports and drains outputs according to their real capacity, parallelism, energy, and processing time. A claimed port or incomplete structure rejects the order.

### Malum

Connect the appropriate soul-processing machine and prepare soul containers, inputs, outputs, and energy. Soul foci or other native retained materials may be preloaded when the route allows them; ordinary consumables should not be preloaded. Extra rewards are collected as actual results and are not assumed to be fixed base outputs.

### Natures Aura

Build the native structure, provide the required aura environment and catalysts, and keep machine inventories available. The packaged route inserts inputs, starts native processing, and collects results; it does not create aura.

### Neo Vitae

Connect the matching machine and prepare its native structure, surrounding components, and energy. Inspected inventories must be idle. Inputs follow the native order, and outputs and returns are recorded from actual recovery.

### Embers

Connect the Ember machine, build its native structure, and provide Ember. Do not share its inputs, outputs, or pipes with another task. Packaged dispatch calls native processing and cannot replace real Ember with an empty container.

### Forbidden Arcanus

Connect the target machine and prepare its native structure, souls, energy, and surrounding ingredients. The packaged route does not bypass ritual, structure, or container checks; input and output slots should be clear before admission.

### Goety

Connect the Dark Altar and prepare activation items, bases, soul cage, and native ritual structure. The packaged route uses its own task player for supported item crafting, enchanting, and locating rituals; experience cost is zero on this route, while souls, structures, and materials remain native requirements. Summoning and entity-transformation rituals are outside this route.

## Reusable inputs

Ordinary consumables scale with dispatch count. Reusable inputs are prepared for the number of physical machines held at the same time and are not returned as ordinary per-round outputs. An adapter can expose reusable custody only when it can report the actual returned item key and amount.

The Imbuement Chamber is the main example: crafting 64 essences needs 64 central consumables plus one catalyst set for each concurrently running machine. Each round is processed by the native chamber; recovered catalysts stay in that session and are returned to the owning CPU when the batch finishes or reaches a safe cancellation point.

Reusable inputs cannot also be declared as ordinary outputs. Session materials, machine progress, session ID, and operation ID are saved together. An unfinished operation is neither refunded early nor inserted again after a reload.

## Removal and recovery

After acceptance, a packaged operation claims its target machine and required shared components. Removing a connector does not make the same inputs available for a second dispatch.

- A chunk unload pauses work; it is not treated as a machine removal.
- Replacing the machine or a claimed component enters removal recovery.
- Removing a provider while it owns work or return inventory can create a packaged recovery receipt.
- Put the same host back at the original position and dimension, leave space in the return inventory, and use the receipt.
- A receipt is single-use and cannot be redeemed for another host type or position.
- Recovery recognizes saved assets only; it does not recreate missing items from recipe expectations.
- Contents that do not fit in the return inventory remain in task state and are retried.

A recovery receipt restores the packaged task and return inventory. It does not repair a structure, supply energy, or re-encode an invalid pattern.

## Staged troubleshooting

| Symptom | First checks |
| --- | --- |
| CPU has inputs but the provider does not accept | Recipe category/ID, provider online state, crafting lock, link target, structure, inventory, and count |
| Provider accepts but machine stays empty | Target face, input mode, machine claim, input capacity, and loaded chunk |
| Machine has inputs but does not start | FE, mana, source, aura, light, native structure, recipe selection, and run switch |
| Machine completes but output remains | Output capacity, output components, returns, and provider online state |
| Output reaches the return inventory but CPU does not finish | ME capacity, exact waiting AE Key, output matching mode, and submission time |
| First round completes but the next is stuck | Leftovers, output slots, batch capacity, structure changes, energy, and runtime errors |
| Removal cannot be recovered | Host type, dimension, original position, receipt state, and return space |

Machines or recipes not listed here do not become supported merely because they belong to one of these Mods. The compatibility list records declared adapter routes; the exact recipe, Mod version, native structure, and real-world behavior still require verification.
